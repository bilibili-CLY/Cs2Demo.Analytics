## P0 — Swing 精度（当前最大误差源）

### [ ] 1. 解析 kit / 拆包开始 tick

- **现状**：csda 只给 `bombsDefused` 的完成 tick 和 `defuserSteamId`，没有 kit 状态、没有拆包开始 tick。
  现在统一用“下包后 10 秒不可逆”的保守阈值，绕过了“有 kit 5 秒 / 正在拆包不限”的官方规则。
- **影响**：残局末段的击杀该不该给 swing 会判错；这是 swing 与官方 corr 只有 0.871 的主要原因之一。
- **方案**：
  1. 先确认 csda 的 `bombsDefused` / `bombsPlanted` 是否带开始/结束 tick、是否有 kit 字段；
  2. 没有就扩展 csda 或在解析层从 demo 事件推导（不改公开 API，`RoundInfo` 加内部字段或新内部结构）；
  3. 规则：有 kit 5s、无 kit 10s、正在拆包不限；同一回合内沿用同一判定。
- **验收**：新增覆盖“有 kit / 无 kit / 拆包中”的单元测试；100 行回归 swing corr 上升，整体 RMSE 不劣化。

### [ ] 2. failed trade 规则

- **现状**：只实现了 5 秒补枪份额（自算窗口），没有实现 failed trade。
- **影响**：HLTV 2026-10 把 trade denial（5 秒内两杀）和 failed trade（5 秒内双方都死，罚后者、奖前者）
  纳入子评分；本库完全没算。
- **方案**：官方语义没有完整公开，先查 HLTV 说明和社区逆向；确认后只进 KAST / MultiKill 子评分，
  **不要硬塞进 swing**（swing 的补枪份额是另一套逻辑）。
- **验收**：单测覆盖“5 秒内双方都死”和“5 秒内两杀”；文档写明与官方的差异；100 行回归不劣化。

### [ ] 3. 地图 / 阵营胜率先验

- **现状**：`SwingCalculator.MapOffsets` 为空，所有图共用全局先验。
- **影响**：`aurora-spirit` 的 anubis / mirage 两张图同时偏低约 -0.05，说明存在按图的系统性偏差。
- **方案**：收集逐图 / 逐阵营的回合胜率（自有 demo 或公开统计），按图拟合偏移；
  样本不足时回退全局（与官方“sample too small → global”一致）；同一回合内概率来源不变。
- **验收**：分图 bias 收敛到 ±0.03；整体 RMSE / corr 不劣化；文档记录数据来源与样本量。

## P1 — 权重与子评分

### [ ] 4. 30–50 张图重拟合权重

- **现状**：权重是 3.1 在 100 行、10 张图上拟合的；3.2 只重算了 eKPR/eADR 的归一化均值，**没有重拟合权重**。
- **影响**：小样本权重已经出现按图偏差；继续在 100 行上拟合会过拟合。
